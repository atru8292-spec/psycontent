# PsyCont — ошибки, которые НЕ повторять

Чек-лист напоминание перед каждой итерацией. Собран из всех прошлых сессий.

## Дизайн / бренд (главное сейчас)
- НЕ делать generic / «вайб-кодинг» вид — это убивает доверие психологов.
- НЕ чистый белый фон → тёплый крем #F7F3EC.
- НЕ дефолтный Inter → Lora (заголовки) + Manrope (текст).
- НЕ синий/фиолетовый AI-градиент, не неон, не красный.
- НЕ одинаковые карточки с тенями как у всех SaaS.
- НЕ показывать список фич на лендинге вместо болей — продавать через боль
  («после сессий нет сил» → режим низкой энергии).

## Продукт
- НЕ делать SMM-щиков целевой аудиторией — продукт их заменяет.
- НЕ сужать нишу жёстко (тёплые vs академичные психологи) — теряем рынок.
- НЕ давать выбор LLM-модели в обычном UX — психологи не разберутся.
- НЕ генерировать «10 признаков…» посты — это контент, который не работает.
- НЕ интегрировать CRM/запись клиентов — чужая территория (PsyAI).
- НЕ строить Telegram-бота на старте — другой UX, отвлечёт. TG только маркетинг.
- НЕ давать много в Free — убьёт конверсию.

## Монетизация
- НЕ делать чистые токены/кредиты — бесит юзеров (отзывы Writesonic).
- НЕ делать «лимит на N генераций» — экономика разваливается (разная стоимость
  операций). Модель: «безлимит» на вид, скрытые лимиты только на дорогое
  (картинки, сторонние API).
- НЕ показывать счётчик каждую секунду — тревожит.
- НЕ списывать за каждую правку — бесит.

## Разработка
- НЕ создавать таблицы вручную в Supabase UI — только миграции в коде.
- НЕ хранить ПДн в БД вне РФ без анонимизации — 152-ФЗ.
- НЕ переписывать с нуля рабочие промпты подходов — модуляризовать.
- НЕ грузить все психологические подходы в каждый промпт.
- Помнить: `supabaseAdmin` (не `supabase`) в трёх роутах: generate-content-plan,
  research-topics, generate-passport.

## Маркетинг
- НЕ запускать платную рекламу пока нет 15-20 кейсов и конверсии >5%.
- НЕ позиционировать как «AI для SMM» → «контент для психологов».

## Процесс (грабли в общении)
- НЕ писать большие документы без согласования — сначала обсудить.
- НЕ выдумывать решения — сначала ресёрч.
- НЕ менять код «в вакууме» — сначала смотреть существующий код.
- НЕ давить в сторону продаж/аутрича, пока продукт не готов — Арина просила.
- Без тире в текстах. Русский, «ты», женский род.
