## КОНТЕКСТ ПРОДУКТА

PsyContent — SaaS для русскоязычных психологов: генерация контента (посты,
карусели, Reels-скрипты, контент-планы, хуки) в их личном тоне, чтобы вести
блог регулярно без выгорания и привлекать клиентов.

Позиционирование (из файла 01): заходить ОТ БОЛИ И РЕЗУЛЬТАТА, не от фич.
«Веди блог, не сгорая на контенте». Продукт = зеркало голоса пользователя.
Две аудитории по тону (мягкие/прямые) — обслуживаются пресетами тона, не разными
продуктами.

Главный ответ рынку (из анализа конкурентов): весь рынок AI-контента жалуется, что
выход звучит генерично и не цепляет эмоционально (≈33% потребителей). Наш центр —
«звучит как ты»: учимся на постах и голосе пользователя. Это не одна из фич, а
главный ответ на главную боль рынка. Держать в центре везде — продукт, UI, копи.
НЕ тащить с рынка: DM-боты и автоответы в директе (яд для доверия психолога),
погоню за виралкой и virality-счётчики (ЦА боится кликбейта), фейковые AI-аватары
(убивают подлинность). Это осознанно отвергнуто.

Стек: Next.js, Supabase (Auth + БД) — ОСТАЁМСЯ на Supabase (переезд на Yandex
отменён, см. решение по БД выше). Приложение может жить на VPS (Германия) или
Vercel. AI — через прямой OpenAI (GPT), НЕ OpenRouter, НЕ Claude (см. раздел
ошибок и шаг 10). РФ-локализацию БД сделать ближе к запуску (дешёвый РФ-хостинг,
не Яндекс).

Текущий код НЕ переписываем с нуля — дорабатываем. Сильная часть: промпты по
11 психотерапевтическим подходам, проработанный онбординг → паспорт бренда.

## Шаг 2 — Схема БД

На Supabase `auth.users` существует, RLS работает. Но чтобы будущий перенос в РФ
был дешёвым, `user_id` в наших таблицах храним как обычный uuid (= id из
Supabase Auth), без жёсткой завязки бизнес-логики на `auth.users`. FK на
`auth.users` допустим только там, где это явно удобно (например users.id), но
бизнес-таблицы ссылаются на user_id как на uuid. Все таблицы — через миграции
в репо (`migrations/`), не руками в консоли. Применять миграции вручную через
SQL Editor (Supabase-коннектор к этому проекту не подключён).

Таблицы фундамента:
- `users` — id(uuid, = Supabase Auth id), email, created_at
- `plans` — id, code, name, price, text_unlimited(bool), energy_per_month(int),
  deep_analysis(bool), is_unlimited(bool), fair_use_text_cap(int)
- `user_subscription` — user_id, plan_id, period_start, period_end
- `energy_wallet` — user_id(pk), balance, monthly_allowance, next_refill,
  total_spent, total_purchased, updated_at
- `energy_transactions` — id, user_id, amount(±), reason, operation,
  balance_after, created_at; индекс (user_id, created_at desc)
- `usage_log` — id, user_id, operation, real_cost_usd, real_cost_rub,
  energy_charged, would_charge, created_at. **Пишется ВСЕГДА.**
- `text_usage_counter` — user_id, period('YYYY-MM'), count (скрытый fair-use)

Контентные таблицы (уже есть в текущей схеме, при необходимости дочистить):
- паспорт бренда (ядро онбординга), сохранённые посты/карусели/планы,
  загруженные образцы постов юзера (для анализа стиля, понадобится в блоке C).

RLS: на всех таблицах с пользовательскими данными включить RLS с политикой по

## Шаг 4 — Энергия и лимиты (логика)

- `/lib/energy.ts`: checkAndConsume(userId, operation), getBalance, refill.

  consume_generation, защита от гонок, месячный сброс).
- Логика checkAndConsume:
  1. Тип операции: текст / картинки / анализ.
  2. План is_unlimited (Тест) → не списывать, записать would_charge + себест в

  3. Текст → проверить fair-use (text_usage_counter). Ок → success + инкремент.

  4. Дорогое → атомарно списать энергию, записать transaction + usage_log.
     Не хватило → отказ + предложить докупку/апгрейд.
  - usage_log пишется всегда, во всех ветках.
- Вставить вызов в роуты ПЕРЕД дорогими операциями. Текст — только инкремент
  счётчика.

### Банк формул Reels (вшить в промпт-движок как отдельный модуль formats/reels/)

Психологи разные — Reels не должны быть однотипными. UI-решение: при генерации
Reels-сценария юзер видит карточки-формулы и выбирает одну (или «удиви меня»).
Генерация идёт строго по выбранной формуле, в тоне архетипа юзера (шаг 11).

Формулы (минимальный стартовый набор, пополняется):

**Ошибка → причина → решение**
Все делают X. Это не работает не потому что Y (привычное), а потому что Z (неожиданное).
Как бы сделала я. Работает у любого архетипа.
Пример: «Тревога не уходит не потому что ты слабая, а потому что ты борешься
с ней вместо того чтобы слышать её.»

**Смена виновника**
Берёшь проблему → обвиняешь не того, кого все привыкли обвинять. Формула:
все думают проблема из-за X, на самом деле из-за Z. Хорошо для экспертного
и прямого архетипа.
Пример: «Клиенты не приходят не потому что мало постов, а потому что в каждом
посте ты пытаешься помочь всем сразу.»

**Состояние → слом → новый взгляд → фраза-якорь**
Заходишь в ситуацию где человек уже находится → ломаешь привычное объяснение
→ даёшь новый взгляд → оставляешь фразу которая остаётся в голове.
Работает для всех архетипов, особенно сильно у бережного.

**Снимаем для одного человека**
Конкретное обращение к одному человеку в конкретной ситуации (не «для всех
женщин», а «если ты снова решила начать новую жизнь с понедельника»).
Структура: обращение → узнавание → мысль → что делать.

**Разрыв шаблона (для смешного/зумерского архетипа)**
Начинаешь с неожиданного, абсурдного или мемного. Контраст между формой и
содержанием: снаружи дичь, внутри реальная польза. Для молодых психологов
которым важна живость а не серьёзность.

**Спорное мнение**
Говоришь то, в чём обычно себя тормозишь. Усиливаешь эмоцией или контрастом.
Добавляешь узнаваемую ситуацию. Без стремления выглядеть идеальным.
Работает у прямого/экспертного архетипа, у бережного — мягче.

Правила для всех формул: начинать с вопроса а не ответа; конкретная ситуация
а не общие слова; один человек а не все; не выглядеть идеальным.
Антипаттерн (этический фильтр режет): давление, страх, «успей», кликбейт.

### Правила качества контента в core (из ресёрча, см. КОНТЕНТ-ЧТО-РАБОТАЕТ-2026.md)

Это инструкции движку КАК генерить (в core/, действуют на все форматы). Они
повышают качество и НЕ плодят одинаковость (в отличие от готовых фраз):
- Хук решает половину. Первые 2-3 секунды / первая строка / первый слайд цепляют
  через узнавание. Хук искренний, не фальшивый (психологи и их аудитория чуют
  фальшь, теряют доверие). Давать и текстовый хук, и идею визуального.
- Удержание: Reels-сценарий с микро-крючками, без затянутого вступления.
  Оптимально 15-30 сек. Не «Привет, сегодня расскажу» — сразу в суть.
- Перебивки: в Reels-сценарии давать раскадровку «здесь покажи X» каждые ~3 сек
  (говоришь о чём-то — покажи). Сценарий = инструкция по съёмке, не только текст.
- Текст на экране: к Reels давать текст-плашки (40% смотрят без звука).
- На сохранение: карусели/посты делать такими, чтобы сохраняли и пересылали
  (чек-листы, техники). CTA не «лайкни», а «сохрани чтобы не потерять» / вопрос
  для комментариев. Сохранения и пересылки важнее лайков (сигнал алгоритму).
- Карусель: первый слайд хук, последний CTA на сохранение; слайды самодостаточны
  но ведут к выводу; сначала мысль и структура, потом дизайн.
- Оригинальность: всегда через паспорт бренда + личный опыт психолога. Алгоритм
  даёт 75% рекомендаций оригиналу, копии трендов не растут. Это и отстройка.

### Как использовать банк болей (НЕ как готовые фразы — критично)

Есть БАНК-БОЛЕЙ-НЕ-В-ЛОБ.md (живые формулировки болей клиентов человеческим
языком). НЕЛЬЗЯ выдавать эти фразы пользователям напрямую как готовые хуки — если
все психологи получат одинаковые фразы, контент выровняется, алгоритм накажет,
отстройка рухнет (та же проблема что у Virale с клонированием).
ПРАВИЛЬНО: банк болей → few-shot примеры в промпте (несколько образцов, чтобы
показать модели ПРИНЦИП «боль через сцену, не диагнозом, через узнавание»). Модель
учится паттерну и генерит СВЕЖИЙ хук под конкретного психолога, его рубрику и
архетип — не достаёт заготовку из списка. Плюс банк — материал для онбординга
(показать психологу как звучат боли его аудитории, помочь сформулировать рубрики).

## Шаг 11 — Глубокий онбординг + анализ стиля [Фаза 1, главный козырь против ChatGPT]

Загрузка 10-30 постов юзера → анализ стиля → обогащение паспорта бренда.
Это закрывает возражение «ChatGPT же бесплатный»: продукт учится на ЕГО постах
и пишет его голосом. Тексты постов перед отправкой в GPT — через анонимизацию.

**Усиление: голосовой онбординг.** Дать опцию проговорить ответы голосом, не
печатать (психолог устал после сессий, говорить легче). Аудио → транскрибация →
заполнение паспорта. Транскрипт перед GPT — через анонимизацию (шаг 6).

**Архетипы психологов (зафиксировать в онбординге, тон генерации зависит от этого):**

Не все психологи бережные и мягкие — аудитория и стиль подачи разные. Три полюса:

- **Бережный/этичный** — тёплый, поддерживающий, без давления. 27-40 лет, аудитория
  такая же. Контент: мягкие инсайты, поддержка, безопасное пространство.
- **Прямой/экспертный** — чёткий, говорит неудобную правду, без сюсюканья. Любой
  возраст. Контент: разборы, спорные мнения, «смена виновника», без розовых очков.
- **Живой/зумерский** — 18-26 лет, смешной контент, мемы, ирония, честность через
  юмор. Аудитория тянется такая же (зумеры идут к молодым психологам). Контент:
  разрыв шаблона, мемный формат, абсурд + польза, лёгкость без потери смысла.

**Что спросить в онбординге (добавить к существующим вопросам):**
- Возраст психолога (влияет на архетип и тон).
- Аудитория: какой возраст, с какими запросами чаще приходят.
- Стиль подачи: бережный / прямой / живой и с юмором (можно показать примеры).
- Готов ли к смешному контенту и мемам (да / иногда / нет).

Результат онбординга фиксируется в паспорте бренда. Промпт-движок (шаг 10)
подтягивает архетип и тон из паспорта при каждой генерации.

**Рубрики психолога (Контент-ДНК) — отдельная фича, собирается в онбординге.**

Сильнейшая механика против одинаковости (подтверждено ресёрчем конкурентов и
скиллом по контент-стратегии). Большинство понимает рубрики как «категории тем»
(тревога, отношения, самооценка) — но это слабо, десятки психологов выбирают те же
категории, контент сливается. Настоящая рубрика = пересечение трёх вещей:
- личный опыт/подход психолога (его школа, его путь, его фишка),
- боль, о которой его аудитория не может перестать думать,
- его уникальный угол на эту боль.
Проверка рубрики: «если убрать имя психолога и это могли бы написать ещё пятеро —
это не рубрика, переделать».

Что делает продукт:
- в онбординге помогает собрать 3-5 таких рубрик (не «темы», а пересечения).
  Банк болей (шаг 10) тут — материал, чтобы показать какие боли бывают и помочь
  психологу найти свой угол, НЕ готовые формулировки.
- вся генерация идёт через выбранную рубрику + архетип + паспорт бренда → хуки и
  посты свежие, в голосе психолога, не из общего списка.
- рубрики хранятся в паспорте, юзер выбирает рубрику перед генерацией.

**На будущее (Фаза 3) — обучающий цикл по рубрикам.** Смотреть, что у психолога
зашло (сохранения/пересылки важнее лайков), и предлагать: копнуть глубже в
рабочую рубрику / смежный угол / проверить новую. Превращает продукт из генератора
в помощника, который растит аккаунт. Не блокер старта, но заложить в модель данных
(хранить какие рубрики/посты заходили).

## Шаг 13 — Карусели: два режима [Фаза 1]

**Два режима (см. ШАБЛОНЫ-КАРУСЕЛЕЙ.md):**
- **Режим Б (главный, бесплатный) — шаблон без AI-картинок.** Психолог вставляет
  СВОИ фото в слоты или берёт текстовый дизайн (типографика + плашки + декор).
  AI-картинки не генерятся → энергию НЕ тратит. Сердце формата, его показывают
  все психологи-рефы (so_anxio_us, s0nyashch, rapitskaya).
- **Режим А (добавка) — карусель по AI-картинкам.** Генерация визуалов через
  OpenAI (gpt-image) для тех, у кого нет своих фото. **Здесь списывается энергия.**

Библиотека шаблонов (не фиксированные 10, а растущий набор — Claude Code может
добавлять новые в рамках бренд-стиля), у каждого: редактируемый текст инлайн,
drag-n-drop элементов, слоты под свои фото, цветовые пресеты + кастом, библиотека
декор-PNG/SVG (стрелки, скрепки, squiggle, обводки — как в Canva). Текст из
генерации льётся в шаблон, дальше юзер правит руками.

Характеры шаблонов (делать разнообразие, не один вид на все):
- Минимал-типографика: крупный заголовок + воздух, одно слово выделено.
- Рукописный: полу-рукописный округлый шрифт для заголовков, тёплый ламповый вид.
- Коллажный с вырезанными PNG-объектами: реалистичный объект без фона (PNG-cutout)
  поверх цветного блока, как в редакторских каруселях (реф Marketing Sharks —
  цепляет «дорого», не шаблонно). Объекты — из стоков/свои фото с вырезкой фона.
- Выделенные слова: ключевое слово на плашке / обведено маркером / другим цветом.
- Фигуры-формы: мягкие кляксы, четырёхлистники, органические пятна как фон-блоки
  (реф Lyla) — текст внутри фигуры.
- Сетка-коллаж: 2-4 фото в сетке + подписи (для кейсов до/после, подборок).
- Цитата/реплика: большая цитата в облаке-реплике (перекликается с лого).

Приоритет: сначала 3-4 базовых (минимал, рукописный, выделенные слова) с пресетами
и текст-редактированием → обкатать → декор → drag-n-drop → коллажный с PNG-cutout
и фигуры → расширять библиотеку → режим А (AI-картинки) последним.

**Цветовые пресеты (расширенная бренд-палитра, всё приглушённое, не кислотное).**

#8F9D68, лаванда #E7E2F2. Родственные пресеты для разнообразия каруселей (тёплые

**Усиление (перенято у PostNitro/Predis): принимать на вход не только эфир, но и
длинный пост, статью или URL** → разложить в набор форматов. «Вставь свою статью
или ссылку → получи неделю контента из неё». Расширяет вау-эффект репурпозинга.

**Вход: своё видео/Reels (то что Арина сейчас делает руками для ресёрча).**
Психолог загружает своё видео → транскрибация (Supadata API, НЕ локальный Whisper:
на сервере локальная транскрибация положит его, для прода только API) → разбор
«что хорошо / что слабо / что улучшить» + переупаковка в карусель, пост, ТГ-пост,
сторис. Боль психолога: «сняла Reels, нет сил на остальное» → один контент даёт
неделю форматов. Ссылку на чужой Instagram-видео качать сложно (IG блокирует),
поэтому свой файл — загрузкой; чужой — отдельная история (см. шаг 17б).

**ТГ-пост — ОТДЕЛЬНЫЙ формат, не копия Instagram-подписи.** Telegram это другая
площадка (проверено ресёрчем):
- лимит: 4096 символов без медиа, 1024 с картинкой; рекомендуется сжато.
- форматирование своё: жирный для мыслей, курсив для цитат, эмодзи как маркеры
  блоков, скрытый текст (спойлер) для интриги.
- нет алгоритма-рекомендаций → ТГ работает на УДЕРЖАНИЕ, не на виральный охват.
  Поэтому первая строка критична (видна в превью канала), а тон глубже и спокойнее
  чем в Reels.
- форматы ТГ у психологов: пост-разбор, лонгрид, практическая техника, личное
  рассуждение, ответ на вопрос подписчика, разбор заблуждения.
Промпт-движок (шаг 10) генерит ТГ-пост по этим правилам, не переливает инсту.

**Воронка Instagram → Telegram (продумать в генерации, не отдельной фичей).**
Стандартная связка: Instagram ловит охват (Reels находят новые люди), Telegram
греет и продаёт (там осознанно подписались, читают вдумчиво, не стыдно звать на
консультацию). Для психолога особенно важно: продавать терапию в лоб в Insta
неловко (их главная боль — стыд продавать), а увести в тёплый ТГ-канал нормально.
Что делает продукт:
- при генерации Reels/поста уметь добавлять мягкую ведущую концовку в ТГ
  («подробнее разобрала в канале», «там же дала упражнение») — НЕ «купи».
- при репурпозинге одного контента: Instagram-версия цепляющая/охватная,
  ТГ-версия — глубже, на удержание. Не копия, а адаптация под роль площадки.
- в подсказках/онбординге мягко объяснять психологу саму воронку (Reels ловит →
  ТГ греет → консультация), многие постят в пустоту не понимая этого.
НЕ делать сейчас: автопостинг сразу в обе площадки, кросс-линки-автоматизацию —
это расфокус. На старте: генерить под обе площадки правильно + мостик-концовка.

2. **Оплата только за успешные** (200/403/404). За 5xx не списывают → ретраи на

## Шаг 17б — Адаптация чужого ролика «под меня» [Фаза 2, метрится энергией]

(добавлено из анализа Virale — у них это сильная фича, у нас не хватало
отдельным понятным сценарием)
Юзер кидает ссылку на чужой залетевший Reels → транскрибация (Supadata) →
LLM-разбор «почему сработало» → адаптированный сценарий ПОД ПАСПОРТ БРЕНДА юзера
(его тон, ниша, аудитория), не копипаст. Прогон через этический фильтр (шаг 14).
Метрится энергией (~20-30).

**Разбор делать по конкретным параметрам (как TrendSee/Virale, не «общими словами»):**
- хук (первая фраза + визуальный хук в первых кадрах)
- длительность и темп (где затянуто, где динамика)
- текст на экране (надписи, субтитры — есть/нет, как используются)
- музыка/звук (роль в удержании)
- монтаж (перебивки, склейки, ритм)
- структура (как развёрнут сценарий по секундам)
- почему зашло (триггеры удержания)
Визуальный анализ кадров — разбирать не только речь, но и что в кадре (обложка +
раскадровка), какие визуальные хуки. Это та «ценная штука», которой хвалится
TrendSee. У нас для этого уже есть механика раскадровки (личный разбор Арины).

Отстройка: весь рынок конкурентов (TrendSee, Virale, ViralMaxing) играет в одну
игру — «найди вирусное → скопируй механику». Даже их юзеры в FAQ спрашивают «это
копия чужого?». Но алгоритм 2026 даёт 75% рекомендаций оригиналу, копии трендов
не растут. PsyCont играет в другое: адаптация через паспорт бренда психолога +
этический фильтр + его рубрики (Контент-ДНК) → оригинальное из его опыта, не
клонирование. Чужой ролик — вдохновение/разбор, не основа. Это совпадает с тем,
что любит алгоритм, и снимает страх «я делаю как все».

## Шаг 17в — Контент-план под цель [Фаза 2]

(усиление существующего контент-плана идеей из Virale)
План на 30 дней строится не «просто идеи», а под выбранную цель: заявки /
подписчики / охваты / прогрев. Юзер выбирает цель в начале, план подстраивает
форматы, хуки и CTA под неё. Темы — ответы на боли аудитории психолога, не вода.
Текстовая операция.

**Роль поста и финал (зашить в генерацию плана и постов, см. ЯДРО-ФОРМАТОВ.md).**
Не каждый пост ведёт к записи. У каждого поста есть роль в воронке, и финал
зависит от роли. Если в каждом посте звать на консультацию — аудитория выгорает.
Три роли (совпадают с полем «цель» формата в ЯДРО):
- **Охват** (верх воронки): задача — досмотрели, подписались, переслали. Финал =
  мысль, образ или вопрос, на котором хочется остаться. CTA нет или мягкий
  («подпишись, чтобы не потерять» / «расскажи в комментариях»). Воронку,
  гайд, директ тут НЕ трогаем. Сюда: мотивационные, вовлекающие, разрушение мифа.
- **Доверие** (середина, прогрев): задача — поверили, что психолог свой. Финал
  тёплый, приглашение в диалог, максимум мягкое «я с этим работаю». Прямой
  продажи нет. Сюда: личные истории, исповеди, закулисье.
- **Запись** (низ, конверсия): только здесь конкретный шаг — гайд, слово в директ,
  консультация, лид-магнит. Таких постов мало.

**Баланс ролей в плане (чтобы движок не делал каждый пост продающим):**
большинство постов — охват и вовлечение, меньше — доверие, совсем мало — запись.
Ориентир пропорции: ~60-70% охват, ~20-30% доверие, ~10% запись (1-2 продающих
поста в месяц на 5-7 прогревающих и 15-20 охватных/вовлекающих). Источник: разбор
контент-воронок психологов; деление «продающий/непродающий» условно — охватный
пост тоже продаёт, просто медленно и без CTA.

## Шаг 17д — Генератор лид-магнитов [Фаза 2, важно для воронки]

(добавлено 24 июня из ресерча воронок психологов, см. КАК-ВЕСТИ-ТГ-ПСИХОЛОГУ.md)
Лид-магнит — бесплатная ценность за подписку/контакт, стартовый механизм воронки
(анонимный читатель → заинтересованный → запись). Многие психологи раздают пользу,
но без следующего шага — воронка обрывается.

Главное правило (зашить в генерацию): лид-магнит ОБЯЗАН вести к следующему шагу.
В конце всегда мягкое предложение (бесплатная консультация / мини-курс / запись).
Без CTA лид-магнит мертв.

Правила рабочего лид-магнита: решает ОДНУ конкретную проблему, быстрый прикладной
результат (не теория), краткий, ведет дальше по воронке.

Форматы (юзер выбирает тип + тему из рубрики, продукт собирает в его голосе):
- чек-лист («5 признаков что пора выдохнуть»)
- гайд/PDF («5 упражнений снять тревогу за 10 минут»)
- тест/диагностика («Выгорание или усталость? пройди тест») — сильный формат,
  персональный результат + понимание боли, легко вовлекает
- мини-практика/аудио-скрипт, шаблон/таблица (дневник эмоций)
- видеопрактикум на узкую тему
Начинать с простого (чек-лист, тест). PDF через WeasyPrint (уже в стеке).

Тест/квиз-конструктор — отдельная сильная подфича (вопросы + персональные
результаты + переход к записи). Фаза 2-3.

Связка с контент-планом: посты-анонсы лид-магнита (рассказать, дать ссылку).
Подсказывать психологу всю воронку: Reels → ТГ/лид-магнит → догрев → запись.

- Скруглённые плашки, мягкие углы, ничего острого.
- Рукописная волнистая линия (squiggle) под заголовками — фирменный элемент.
- Винтажные ч/б коллажи с одним зелёным (шалфей) акцентом, аналоговая фактура,
  без глянцевого 3D (где уместны иллюстрации).

Тон голоса в UI: спокойный, тёплый, на доверии. Без «успей», «измени жизнь»,
давления. Конкретика вместо абстракций. Заголовки до 6 слов.

## Общие принципы интерфейса

- **Заход от боли и результата**, не от фич (файл 01). Заголовки экранов и пустые
  состояния — про результат («Веди блог, не сгорая»), не про кнопки.
- **Слово «энергия»**, не кредиты/токены/рубли.
- **Тексты UI** (микрокопия, ошибки, пустые состояния, онбординг) — без тире «—»,
  без anti-slop клише из файла 05, человеческим языком.
- **Простота**: ЦА невысокого тех-уровня (файл 02). Минимум полей, ясные действия.
- **Два полюса тона** видны уже в онбординге (пресеты тона мягкий/прямой).
- На тексте — никаких счётчиков. Энергия — только на дорогих экранах.
- Паспорт бренда — центральный объект кабинета (ядро блога, из него всё).

Конкретные экраны под фичи (онбординг с загрузкой постов, тон-контроль кнопками,
конструктор каруселей, отчёты анализа конкурентов, репурпозинг) проектируются
в шагах 11-18 соответственно, каждый со своим UI.

## Структура продукта и навигация (ОБНОВЛЕНО 24 июня)

Главный принцип: продукт ВЕДЁТ, а не ждёт команды. Враг психолога — пустой экран
и вопрос «что постить». Поэтому дом = контент-план, а не пустой генератор.

Путь юзера: регистрация → тизер → быстрый онбординг → контент-план (дом) →
генераторы форматов → результат/правки/экспорт.

**Тизер после регистрации (перед онбордингом).** 3-4 экрана / 30-60 сек: что умеет
сервис, примеры готового контента, обещание. Цель — мотивировать пройти распаковку,
показав ценность. С кнопкой пропустить.

**Онбординг разбить на уровни (борьба с отвалом).** Текущий MVP-онбординг — 22
вопроса / 25 минут, это много, большой риск бросить на старте. Решение:
- Быстрый старт: 5-7 ключевых вопросов (имя, ниша, тон, аудитория, цель). Хватает
  чтобы начать генерить. ~3 минуты.
- Полная распаковка: остальное, опционально, дозаполнять позже из профиля по
  блокам. Прогресс «паспорт заполнен на N%», мягкий намёк что точность контента
  растёт с заполненностью.
- Везде «пропустить / заполнить позже». Не блокировать принуждением, но показывать
  выгоду. Демо-режим (заполнить примером) — оставить, удобно для пробы.

**Дом = контент-план.** Главный экран после входа — план на неделю/месяц («Пн —
Reels рубрика Тихая тревога, Ср — карусель, Пт — ТГ-пост»), построенный под
воронку Insta→TG и под цель (охваты/записи). Карточка плана → тап → генерация
нужного формата с подставленной темой и рубрикой. Это и есть анти-выгорание.

**Отдельные генераторы** (входы из плана и из меню, как в MVP, но связаны планом):
генератор постов, карусели, рилс-сценарии, хуки, ТГ-пост, сторис, переписать/
мысль→контент, адаптация чужого ролика. Структура по типам сохраняется (психолог
приходит с конкретной задачей), план их связывает чтобы не теряться.

**Что зашло** (Фаза 3): обучающий цикл, план подстраивается под сохранения/пересылки.

## Голосовой ввод и мысль→контент (ОБНОВЛЕНО 24 июня)

**Голосовой ввод везде, где вводится текст** (тема, распаковка, правки) — кнопка
надиктовать. Психолог устал печатать, речь быстрее и живее. В проде транскрипция
через API (Supadata/аналог), не локальный Whisper.

**Мысль→контент** (подтверждено ресёрчем конкурентов 2026: Reframe, Draft AI,
WaveGen — топовые делают именно это). Психолог надиктовывает/пишет сырую мысль →
AI структурирует в карусель/пост/сценарий, сохраняя ЕГО голос. Двойной режим:
взять мысль как есть и оформить, ИЛИ предложить 5 тем/углов под рубрику на выбор
(снять ступор «о чём писать»). Реф Draft AI: свайп-режим тем (тиндер для идей) —
рассмотреть. Принцип: мысль психолога = основа (оригинальность), AI только
оформляет, не подменяет голос на нейронный.

**5 релевантных тем на выбор.** Генератор всегда предлагает 5 тем под рубрику +
архетип + паспорт (из пересечения опыта психолога и боли аудитории, не общие).
Выбрать или сгенерить свои.

**Тон — и в онбординге, и в генераторе.** Онбординг задаёт базовый голос (дефолт,
ползунки + вербальный стиль). Генератор даёт быструю подстройку тона под конкретный
пост поверх дефолта (обычно мягкая, но этот пост прямее). Не переспрашивать весь
тон, дать быстрые кнопки.

## Генератор каруселей — мини-канва (ОБНОВЛЕНО 24 июня, дополняет шаг 13)

Самая сложная по UI часть, делать сразу продуманно. Принцип (рефы Reframe, Mirra
Carousel Lab, PostNitro): AI делает каркас (структура слайдов 6-10, черновик текста,
первый слайд хук, последний CTA на сохранение), психолог дорабатывает в редакторе.
«AI каркас, человек голос» — не полный Figma, а удобно под карусели.

В редакторе: правка текста, пресеты палитр из бренда (14 пресетов + кастом, см.
шаг 13), шрифты с кириллицей, SVG-декор (код-генерируемый), сток-фото и мемы по
API, режим B (свои фото, без энергии) и A (AI-картинки, энергия), cutout (шаблон
11, не первый шаг). Размер Instagram 4:5 (1080x1350) база.

**Экспорты (важно, делать удобно):** PNG каждого слайда + ZIP всех разом; PDF всей
карусели (LinkedIn/Telegram-документ); сохранение в проект/историю с возвратом к
правке; кнопка «переупаковать в пост/ТГ» из той же карусели. PNG через рендер,
PDF через WeasyPrint.

## ЛЕНДИНГ — ПРИНЦИПЫ КОНВЕРСИИ (из разбора сильных SaaS-сайтов, 25 июня)
Применять при переделке лендинга, поверх захода «от боли и результата» (файл 01):
- **Оффер понятен за 3 секунды.** Первый экран сразу говорит, что психолог

- **Показывай, а не рассказывай.** Сильнее всего сработает живое демо генерации:
  показать, как из пары кликов рождается готовый пост в голосе психолога. Статика

- **Прозрачные тарифы.** Видно, что входит в каждый (Free/Старт/Практика/Эксперт),
  чтобы психолог сразу понял, вписывается ли в бюджет.
- **Соцдоказательство — когда появится реальное.** Сейчас отзывов нет, выдуманные
  убрать. Как появятся 2-3 реальных от тестовых психологов или скриншоты
  сгенерированного контента — добавить, это сильно поднимает доверие.
- **Минимализм и единая айдентика.** Воздух, бренд-цвета и Onest, без emoji-россыпи
  и generic-карточек. Доверие строится чистотой.
